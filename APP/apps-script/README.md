# 旅伴 roam 共用版

本目錄是 Google Apps Script Web 應用程式的原始碼。現有的 GitHub Pages 入口仍提供本機原型。

## 更新既有部署

1. 使用有權編輯試算表、也能部署既有 Apps Script 的 Google 帳號，從指定的 Drive 資料夾開啟既有專案。若專案綁定試算表，可從試算表的「擴充功能 → Apps Script」開啟。
2. 在編輯器左側「檔案 → ＋」新增指令碼 `Roam.gs` 和 HTML `Roam.html`，貼入本目錄的內容。先檢查既有 `doGet`、`doPost` 和公開函式。專案只能有一個 `doGet`，請保留新版入口，並在公開部署前移除或限制任何可以繞過新版旅程權限的舊讀寫入口。既有程式或分頁若另有用途，請先確認相容性。
3. 到左側齒輪「專案設定 → 指令碼屬性 → 新增指令碼屬性」，將 `ROAM_SHEET_ID` 設為指定試算表網址中 `/d/` 與 `/edit` 之間的 ID。若既有清單明列 OAuth 範圍，須包含試算表讀寫權限 `https://www.googleapis.com/auth/spreadsheets`。確認執行階段為 V8。
4. 回到編輯器，在上方函式選單選 `roamSetup_`，按「執行」，由擁有者完成 Google 授權。它只會新增缺少的 `Roam_旅程`、`Roam_旅伴`、`Roam_行程`、`Roam_支出` 分頁，並檢查同名分頁的欄名。遇到欄名不符時，先核對既有資料。
5. 選右上「部署 → 管理部署」，選既有 Web 應用程式部署，按鉛筆後選「新版本」。執行身分選「我」，存取權選「任何人」，按「部署」。若帳戶沒有允許匿名存取的「任何人」選項，需由有該選項且可編輯試算表的帳戶部署。
6. 在「管理部署」複製正式 `/exec` 網址，將其設為指令碼屬性 `ROAM_WEB_URL`，讓邀請固定使用這個部署。再次執行 `roamSetup_`，從執行記錄複製含 `#organizer=` 的主辦人網址並私下保存。訪客使用 Apps Script 網頁，試算表與 Apps Script 專案的分享權限可維持原設定。

部署步驟依 [Google Apps Script Web Apps 指南](https://developers.google.com/apps-script/guides/web)。

## 主辦人管理

打開主辦人網址，按「建立旅程」，設定名稱和日期。按該旅程的「建立邀請」並複製連結給旅伴。已有連結時按「取得邀請」可再複製。按「撤銷」後，舊連結在下一次讀寫即被拒絕，再按「建立邀請」即可取得新連結。

所有持有有效旅程邀請的人都可以編輯該旅程。主辦人網址可管理所有旅程的邀請，請只分享個別旅程的邀請網址。金鑰由 Apps Script 產生並保存在指令碼屬性。旅程、旅伴、行程和支出的資料由指定試算表保存。直接改工作表資料時，請保留第一列的欄名與各筆 ID。金額欄以新台幣元計。

共用版建立的新旅程沒有預設角色、行程或帳目。本機原型另有瀏覽器資料。既有 Apps Script 和試算表內容要在取得存取後核對，才能判斷哪些是可辨識的未修改測試資料，以及如何轉入共用版。

## 正式驗收

1. 主辦人建立獨立的驗收旅程和邀請。用兩個獨立、未登入 Google 的瀏覽器或訪客工作階段開啟同一個邀請。
2. 用瀏覽器 A 新增一位旅伴、一筆行程及一筆由該旅伴付款的支出。瀏覽器 B 重新整理，確認三筆資料、代墊金額和旅程支出總額。
3. 在指定試算表的 `Roam_旅伴`、`Roam_行程` 和 `Roam_支出` 核對資料列，將 `Roam_支出` 的金額改為另一個值。重新整理瀏覽器 B，核對明細、代墊和總額。
4. 在兩個未登入的瀏覽器以裸的 `/exec` 網址和改動過的邀請測試，應無法看到旅程或操作。撤銷原邀請後，在仍開著的瀏覽器 A 嘗試新增一筆資料，應收到拒絕且試算表沒有增加資料。重新整理瀏覽器 B 時也應拒絕讀取。
5. 本機的 `node --test tests/*.test.mjs` 使用模擬 Apps Script 與試算表服務。正式驗收須依以上步驟在實際部署後執行。
